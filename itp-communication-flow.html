Interpersonal Transaction Protocol · schema v0.2

How one ITP communication flows through the codebase

A single interaction is a sequence of nested ITP messages passing between formal models. Every message is produced, validated, stored, converted when state spaces differ, and integrated — never mutated in place. This maps each step to the class and method that performs it.

02 What flows — the ITP message (v0.2)

The single object passed between every participant. Only values.data is integrated by a receiving model; everything else is routing and provenance.

{
  schema_version: "0.2",
  source_agent: { id, state_space, analysis_unit },
  target_agent: { id, state_space, analysis_unit },
  timecode: { timestamp, interaction_turn },
  values: { state_space, analysis_unit, data: { dim: number } },
  context: "workplace_colleague_conversation",
  metadata?: { message_type, conversion }
}

03 The two communication flows

Read each column top to bottom — it is one message crossing from a source to a target. The reply repeats it with the roles swapped, and the runner loops for N turns.

Local interaction

run_local_interaction.py — two in-process models

Source model
source.to_message(target_agent, timecode, context) Calls generate_numerical_output(), wraps it with make_values() / make_agent() / make_message().
returns original message▼
Communication
receive_message(original) Validates via ITPSpecification, stores a deep copy — message_type: original.
prepare_message_for_target() · needs_conversion?▼
ConverterRegistry
convert_message(original) Only when values.state_space ≠ target.state_space. Picks e.g. SASBToIPCConverter, rewrites values.data, tags metadata. Missing mapping raises. If spaces match, this step is skipped.
receive_message() · store converted▼
Communication
receive_message(converted) Converted copy stored alongside the original — full provenance kept.
deliver▼
Target model
target.from_message(delivered) Checks target id + state_space + analysis_unit, then integrate_numerical_input(values["data"]).

Then roles swap for the reply. After all turns, communication.save_messages() writes every original and converted message to results/<timestamp>/.

API remote interaction

run_API_interaction.py + run_model_api.py — across processes

APIClient → APISpecification
get_info() · GET /info Remote returns {agent, dimensions, schema_version}; agent = remote.to_agent().
POST /generate (target_agent as dict)▼

generate_message() → remote.to_message() Remote model produces a nested ITP message and returns it over HTTP.
receive_message() + prepare_message_for_target()▼

store original → convert if needed → store converted Same store-both-copies rule as the local flow; conversion is conditional on state space.

Local model

The Communication session lives on the client side and records every message that crosses the wire, original and converted.

04 Rules the flow keeps

Communication stays pure

It validates and stores messages only — never holds a model, client, or user. Orchestration lives in the runners.

Conversion is external & conditional

Applied by prepare_message_for_target, not by the session or the model. Skipped when source and target share a state space.

Models integrate data only

from_message reads values["data"] and rejects any message whose target id or state space does not match.

Provenance is preserved

Both the original and the converted message are stored, and conversions record their converter in metadata.
