# Interaction report example

The run behind Figure 2 of the ITP paper, its report, and the two further dialogs of
Electronic Supplementary Material 1 (Figures E7 to E10, Tables E4 to E6).

Open `interaction_report.html` in a browser. It needs no server and fetches nothing. The slider
steps through the eight turns. *Download SVG* and *Download PNG* export the figure at the selected
turn; the paper shows turn 8. The figure is laid out for a landscape page (9 in wide).

## What is here

| File | What it is |
|---|---|
| `record/20261029_115431_ea745c6f/` | The ITP record behind the figure: `interaction.json` and one file per ITP message |
| `lassi_record/20261029_115437_61767b18/` | The other agent's record of the same dialog (LASSI), for reference |
| `dialogue.csv` | The text of each turn of `record/`, joined on `turn` and `role`, from the PerTRAIN database |
| `lassi_dialogue.csv` | The same for `lassi_record/` |
| `interaction_report.html` | The report written from the record and the dialogue |
| `dialog2/`, `dialog3/` | The two further dialogs of the same run: `ipc_record/` and `lassi_record/`, a dialogue file and a report for each (`ipc_dialogue.csv`, `ipc_report.html`, `lassi_dialogue.csv`, `lassi_report.html`) |
| `pertrain_dialogue.py` | Writes `dialogue.csv` for a PerTRAIN record (see below) |

## The interaction

A conflict in a bar, run between two PerTRAIN agents on a local PerTRAIN stack against a local
ITP server, with the collection `ITPGenerator Test` of the PerTRAIN configs. Daniel Becker
confronts Lukas Wagner about a joke he overheard and took to be about his missed chance in last
Sunday's match. Lukas told it about a viral clip and did not mean him. Every message is generated
by gpt-4.1 and assessed on agency and communion by gpt-5.4. Daniel's opening line comes before any
model has answered, so it is written at the start state of the PerTRAIN collection (`start_state: 3`,
counted from 0, which is 4, neutral, on both axes); from his second message on, LASSI sets his
state. The dialog has eight messages, four per agent (PerTRAIN dialog `3266e74a`).

Each PerTRAIN agent is steered by its own ITP interaction, with the partner's assessed messages as
human agent A in `ac` and a hosted model as agent B:

- Lukas is steered by the dummy IPC model (`dummy-ipc`) in the interpersonal circumplex. This is
  the record in `record/` and the one the figure shows: agent A is Daniel's text as assessed in
  `ac`, agent B the dummy model's behavior, and every turn crosses state spaces, so each is stored
  twice, as sent and as converted for the partner.
- Daniel is steered by LASSI (`lassi`) with A: BD 5.5, IR −0.6 and C: BD 3, IR 0.7, set by his
  PerTRAIN template through the agent's `configuration`. This is the record in `lassi_record/`. Both
  sides speak `ac` there, so nothing is converted. It holds six turns, because the last message
  reached the dialog's end before the ITP.

Neither record contains both models: in PerTRAIN the two agents are coupled through their texts.
Each agent's own assessor rates the partner's messages, and the PerTRAIN interface takes part in
`ac`, the space of that rating. The platform converts between it and the model as it would between
two models, so Lukas's records convert every message (`ac` and `ipc`) and Daniel's convert nothing.
The legends name the partner's side "assessed messages" for that reason: its points are the
partner's text as rated, not the states the partner's model set.

The same run produced two further dialogs with the same scenario and models, in which only Daniel's
LASSI parameters differ: in `dialog2/`, A: BD 3.5, IR 0.8 and C: BD 5, IR 0.8 (PerTRAIN dialog
`1ec16a96`); in `dialog3/`, a random draw by the platform, A: BD 4.37, IR 0.11 and C: BD 2.91,
IR −0.27 (dialog `eec1ed07`). Each holds both records. In Daniel's records the opening line has no
turn, and the last turn holds the state LASSI set for a message the ended dialog never sent.

A new run gives different text and numbers, because the language models and LASSI sample. The
records here are therefore the reference, not the run.

## Rebuild the report

From the repository root:

```bash
python -m src.run_interaction_report examples/interaction-report/record/20261029_115431_ea745c6f \
    --text examples/interaction-report/dialogue.csv \
    --text-source "PerTRAIN dialog 3266e74a on the local stack; messages generated by gpt-4.1, assessed in AC by gpt-5.4" \
    --label A="Daniel Becker (assessed messages)" \
    --label B="Lukas Wagner (dummy IPC model)" \
    --title "Bar conflict over a joke, from the side of Lukas's model (dummy IPC); Daniel steered by LASSI (A: BD 5.5, IR -0.6; C: BD 3, IR 0.7)" \
    --time-space ac --print-width landscape \
    --out examples/interaction-report/interaction_report.html
```

The reports in `dialog2/` and `dialog3/` are built the same way, from the record and dialogue file
of the same name. In a LASSI record, agent A is Lukas, labelled "assessed messages", and agent B is
Daniel with his parameters, for example
`--label A="Lukas Wagner (assessed messages)" --label B="Daniel Becker (LASSI: A: BD 3.5, IR 0.8; C: BD 5, IR 0.8)"`.

## Text from a PerTRAIN dialog

`pertrain_dialogue.py` writes the dialogue file for a record that PerTRAIN's `ITPGenerator`
produced, from the messages in a local PerTRAIN stack (`podman exec pertrain-db-postgres psql`).
Such a record has the agent's partner as human agent A in `ac` and the model that steers the agent
as B, and its `clientRequestId` is the PerTRAIN session. A's k-th turn is the k-th partner message
as PerTRAIN's assessor rated it; B's k-th turn is the state the model returned, and its text is the
agent's own message that follows. An opening line the agent sends before any partner message has
no turn. A record whose turns do not match the messages is refused. `dialogue.csv` here was
written this way from `record/`.

```bash
python examples/interaction-report/pertrain_dialogue.py results/<folder> --out dialogue.csv
python -m src.run_interaction_report results/<folder> --text dialogue.csv \
    --text-source "PerTRAIN dialog <id>"
```

One record holds one model. A dialog between two PerTRAIN agents steered by two models leaves two
records, one per agent, and in each the partner appears as assessed text.
